Concept 04前端工具

工具让智能体动手做事。后端工具在服务端跑，页面只展示过程；前端工具在浏览器里跑，还能弹出你自己的 React 组件让用户选择。

01

defineTool

tools/getBrowserTime.ts
import { defineTool } from "@auipage/react";

export default defineTool({
    name: "getBrowserTime",
    description: "获取当前浏览器所在设备的本地日期与时间",
    parameters: { type: "object", properties: {}, required: [] },
    execute() {
        return new Date().toLocaleString();
    },
});
字段类型必填说明
namestring是工具名，对应 description.function.name，模型据此发起调用。
descriptionstring是给模型看的功能说明。
parametersobject是入参 JSON Schema。
execute(args) => unknown否页面侧执行函数；缺省时兜底为空执行，让 render 依然能收到 success。
renderComponentType<ToolRenderProps>否工具渲染组件；缺省时该工具退化为纯调用，只显示结果。

core 对前端工具是无判空调 execute 的，React 版统一兜底为 () => null， 所以只挂 render 的纯交互工具也能正常进入 executing 态。

02

渲染组件的 props

实时态与历史回读态共用同一套字段，避免回读漏字段导致 UI 不一致：

types.ts
interface ToolRenderProps {
    args: any;                                // 模型解析出的入参
    result?: any;                             // execute 的结果（异常时为错误对象）
    status: "pending" | "success" | "error";  // execute 状态
    uiResult?: unknown;                       // 历史回读：当时交还的结果
    uiStatus?: "success" | "error";           // 历史回读：交互状态
    call?: (result: unknown) => void;         // 实时态：交还结果并结束挂起
}

判断态的规则只有一条：

  • 有 call → 实时态，交互完成后调用 call(result) 把结果交还 core。
  • 没有 call → 历史回读态，用 uiResult / uiStatus 只读展示。
03

交互式工具示例

tools/askFavoriteFruit.tsx
const FRUITS = ["苹果", "香蕉", "橙子", "葡萄", "西瓜"];

function AskFavoriteFruitRender({ call, uiResult, result, status }: ToolRenderProps) {
    // 历史回读：只读展示
    if (!call) {
        return <span>已选择：{String(uiResult)}</span>;
    }

    const fruits: string[] = status === "success" && Array.isArray(result) ? result : [];

    return (
        <div className="fruit-picker">
            <div>请选择你喜欢的水果：</div>
            {fruits.map(fruit => (
                <button key={fruit} type="button" onClick={() => call(fruit)}>
                    {fruit}
                </button>
            ))}
        </div>
    );
}

export default defineTool({
    name: "askFavoriteFruit",
    description: "当需要了解用户喜欢什么水果时使用",
    parameters: { type: "object", properties: {}, required: [] },
    execute() { return FRUITS; },
    render: AskFavoriteFruitRender,
});

完整链路：execute 拿候选数据 → core 回调 { render, status, result } → 卡片切到 executing 并挂载组件 → 用户点击 → call(fruit) → core 回传 response("tool-result", ...) → 再次回调写入 uiResult，组件转为只读态留在页面上。

04

生命周期

一个 tool-call 在 store 里是单个 part，靠稳定 id 贯穿，phase 原地切换：

phase
pending → executing → result
phase触发界面表现calluiResult
pending流中首次收到 tool-call名称 + 入参 + 运行中无无
executing带 render 的工具 execute 完成挂载 render 组件有无
result后端工具 / 无 render 工具结束结果卡片无无

带 render 的工具在 executing 之后还会再回调一次： call 完成后写入 uiResult、清空 call，phase 仍是 executing， 组件自然切到只读态 —— 节点不会重建。

05

历史回读与后端工具

  • 工具仍注册：历史里还原成只读 executing 形态，用 uiResult / uiStatus 驱动。
  • 工具已下线或无 render：统一降级为 result 形态的结果卡片。
  • 后端工具：对 React 侧透明，流里同样是 tool-call 片段但没有 render，直接走 pending → result，不挂任何组件，业务侧无需注册。
所以 render 组件必须同时处理两种态。只写实时态、忽略 !call 的分支， 历史会话里这块工具就会渲染失败。
