Concept 02适配器

适配器是组件库与你的后端之间唯一的接缝。core 只认三套接口，业务侧实现它们，就能把任何 HTTP / SSE / WebSocket 接进来。

ChatTransportAdapterMessageHistoryAdapterThreadListAdapter
01

装配方式

三个实例按固定 key 组装，传给 Provider：

adapter.ts
const adapter = { ChatTransport, MessageHistory, ThreadList };

key 是约定死的：ChatTransport / MessageHistory / ThreadList， core 内部按这几个名字取实例，改名会直接报错。

02

ChatTransport：对话接口

chatTransport.ts
new ChatTransportAdapter({
    async *run({ messages, context }) { /* ... */ },
    response(name, data) { /* ... */ },
});
字段类型说明
run(params) => AsyncGenerator<ContentPart>发起一轮对话，逐个 yield 片段。返回假值（void / null）时 core 直接结束本轮。
params.messagesChatContentMessage[]本轮新发送的消息（role + content 片段数组）。当前实现每轮一条，但保留数组形态。
params.context.historyHistoryMessageGroup[]当前会话已入库的历史消息组，可预处理后再喂模型。
params.context.tools{ description }[]页面注册的工具描述，可直接序列化随请求发给模型。
response(name, data) => unknown反向通道。目前只用于前端工具结果回传：response("tool-result", { id, status, result })。

把回调式流读转成 AsyncGenerator，用 generator 包一层即可：

chatTransport.ts
import { ChatTransportAdapter, generator } from "@auipage/react";
import { fetch } from "@auipage/fetch";

new ChatTransportAdapter({
    async *run({ messages, context }) {
        // 思考态占位
        yield { type: "loading", text: "思考中..." };

        yield* generator((callYield, callEnd, callError) => {
            fetch({
                url: "/api/chat",
                method: "POST",
                headers: { "Content-Type": "application/json" },
                body: JSON.stringify({ messages, tools: context.tools }),
            }).then(res => {
                res.on("data", chunk => callYield(JSON.parse(chunk)));
                res.on("end", callEnd);
                res.on("error", callError);
            }).catch(callError);
        });
    },
    response(name, data) {
        return post("/api/chat/" + name, data);
    },
});
03

MessageHistory：历史读写

messageHistory.ts
new MessageHistoryAdapter({
    async load(threadId) { /* HistoryMessageGroup[] */ },
    async append(threadId, group) { /* void */ },
});
  • load 在切换会话时调用；返回假值时 core 跳过历史加载（新会话场景）。
  • append 每轮结束后把一整组消息写入会话，group.messages 与 run 收到的结构同构。
  • 入库时不用手动剔除 loading 片段 —— 运行时渲染历史时会自动过滤。
04

ThreadList：会话管理

threadList.ts
new ThreadListAdapter({
    async list() {},
    async new(firstGroup) {},
    async archive(threadId) {},
    async unarchive(threadId) {},
    async delete(threadId) {},
});
方法入参返回行为
list无Thread[]Provider 挂载时立即调用一次。
newHistoryMessageGroupThread | void用首轮消息建会话；返回假值会中止本轮后续流程。
archivethreadIdvoid归档；归档的是当前会话时自动切到新建态。
unarchivethreadIdvoid取消归档，不自动切换会话。
deletethreadIdvoid删除；删当前会话时自动切到新建态。

会话对象的最小约定：

types.ts
interface ThreadListItem {
    threadId: string;                 // 必填，列表 key 与操作都靠它
    title: string;
    status: "regular" | "archived";
}
05

片段数据形态

run 里 yield 的就是 ContentPart：

part
{ type: "text",     text: "正文增量" }
{ type: "thinking",  text: "思维链增量" }
{ type: "loading",  text: "思考中..." }
{
    type: "tool-call",
    id: "call-xxx",          // 单次调用唯一标识，用作 part 稳定 key
    name: "askFavoriteFruit",
    args: { /* ... */ },
    status: "success",       // 终态时补齐
    result: /* ... */,
    render: ToolComponent,   // 带 UI 的前端工具才有
    ui: { status, result },  // 落库时记录 UI 交互结果
}
文本类片段是增量拼接的。同类型连续片段会合并到同一个 part 的 text 上， 而不是每来一片就多一个 part —— 所以流式输出在 DOM 上是一段文字在变长，不是不断新建节点。

业务可以 yield 任意带 type 的对象（如 { type: "image", url }），运行时会原样放进 parts， 由 ChatContent.Parts 的 render-prop 自己决定怎么渲染。
