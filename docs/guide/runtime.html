Concept 05数据流与状态

Provider、zustand store 与 core 编排器是三层分工：core 只管流程，runtime 把命令式回调翻成 setState，组件订阅 store 渲染。

AuiPagezustandruntime
01

四层结构

layers
React 组件层        ChatContent.* / ThreadList.*
      ▲ 订阅 store            │ 调 aui.* 触发动作
      │                       ▼
状态层              zustand store（messages / threads / isExecuting ...）
      ▲ setState              │
      │                       ▼
运行时层            makeChatContentRuntime / makeThreadListRuntime
      ▲ 命令式回调            │
      │                       ▼
编排器层            AuiPage（@auipage/core），串联 adapter 与 runtime
  • AuiPage：不感知 React，只认 adapter 与 runtime 两套接口。
  • runtime：把 core 的 init / append / active ... 翻译成 store 更新。
  • store：React 侧唯一状态源，组件用 selector 订阅。
  • 组件：useAuiContext() 拿 { aui, store }，调动作、渲 UI。
02

store 形态

store.ts
interface AuiStoreState {
    messages: ChatMessage[];            // 当前会话消息列表
    threads: ThreadListItem[];          // 会话列表
    activeThreadId: string | undefined; // 当前激活会话；undefined 表示新建会话
    isExecuting: boolean;               // 是否在对话执行中
    composerValue: string;              // 输入框当前值
}
03

append 的翻译规则

core 调 runtime.ChatContent.append(role, content)，运行时按 content.type 分支：

  • text / loading / thinking：并入最后一条同 role 消息的 parts（不存在则新建），并返回一个 (delta) => void 的流式更新函数，后续增量直接往 text 上拼。
  • tool-call：先建 pending part（稳定 id），返回结束回调； 后续按 data 形态走「挂 render 进 executing」或「直接进 result」。
  • 其它：原样转成 ChatContentPart 追加。
同 role 合并是硬约束。最后一条消息 role 与本次相同就并入 parts，这样实时态 DOM 与历史回读 DOM 结构一致， 同一套渲染逻辑能吃两种态。
04

一次发送的完整链路

  1. 输入框 / 发送按钮调 sendMessage(aui, store)。
  2. 读 composerValue，trim 为空或 isExecuting 时直接 return；否则清空输入框、置 isExecuting = true。
  3. AuiPage.sendMessage：append 用户消息 → ThreadList.new（新会话时）→ MessageHistory.append → 调 ChatTransport.run。
  4. core 逐个消费 generator：text 走流式拼接、tool-call 建 part、终态按有无 render 分支。
  5. generator 结束，Promise resolve，isExecuting 复位，发送按钮恢复。

期间每次 setState 都触发 zustand 通知； Viewport 订阅消息数量与文本总长度，所以流式增量也会触发滚到底。

05

多实例与错误处理

  • 多实例隔离：Provider 用 useRef 保证单实例只装配一次，不同 Provider 各有独立 store 与 AuiPage， 同一个 React 树里可以并排两个（多账号多窗口）。
  • 执行中重复发送：sendMessage 内部 catch core 的 reject，只 console.error，不向上抛。
  • 上下文缺失：三个 hook 抛错并给修复提示。
  • 自定义错误：外层包一层 aui.sendMessage，或监听 store.isExecuting 做自己的反馈。
